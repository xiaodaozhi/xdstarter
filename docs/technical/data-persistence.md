# 数据与持久化

对应需求：PRD-002、PRD-004、PRD-006、PRD-007。

## 标识与数据职责

- `appId`：应用目录中的稳定标识。优先使用平台应用标识，快捷方式使用规范化目录项身份。
- `targetId`：已固定启动目标的内部标识；保存足够的启动描述，目录刷新不随意移除用户磁贴。
- `tileId` / `groupId`：生成后保持不变，用于拖拽、焦点、持久化与更新模型。
- `iconKey`：可重建的图标缓存键，不作为应用身份。

用户布局与偏好是权威数据；应用目录和搜索索引为可重建缓存。启动描述区分 `.lnk` 快捷方式和打包应用 AUMID，不把任意命令拼接成 Shell 字符串。

## 首版配置方向

使用 UTF-8 JSON，根包含 `schemaVersion: 1`、分组、磁贴、启动目标与偏好。磁贴保存 size 枚举、整数 row/column 和 targetId。偏好包含主题、菜单大小和用户选择的接管/开机启动选项。

路径通过 `QStandardPaths::AppLocalDataLocation` 获取，目录身份与产品名称在工程初始化时固定。日志和缓存单独存放，不能写入源码目录或程序安装目录。

## 保存和恢复

1. 内存中生成完整快照，校验版本、引用、尺寸、格坐标与碰撞。
2. 使用 `QSaveFile` 写入并提交；保留最近一次校验通过的备份。
3. 合并短时间内的编辑保存，避免每个指针事件写盘；退出时等待当前保存任务完成或保留上一次有效快照。
4. 读取失败先尝试有效备份，再恢复默认布局并提示；保留损坏文件便于诊断。
5. 遇到高于当前支持的版本时不覆盖文件；进入只读/恢复提示，避免旧版本破坏新配置。

目标卸载或路径失效与配置损坏区别处理：保留磁贴位置并标记不可用，允许重新选择或取消固定。首次没有配置时使用简单默认分组，不擅自固定未安装的示例应用。

## 搜索索引

保存名称的大小写归一化形式、别名及拼音键，索引只在目录变化后增量更新。拼音提供者及词库许可在对应 Issue 中确认后引入，不在 QML 中硬编码大词表。排序规则遵循[交互设计](../product/interaction.md)。

导入配置视为用户数据：校验版本、结构、数量和目标类型，预览后再替换当前布局；导入不自动执行任何启动目标。
