# 数据与持久化

对应需求：PRD-004、PRD-007；保存恢复由 [#10](https://github.com/xiaodaozhi/xdstarter/issues/10) 跟踪，应用目标由 [#7](https://github.com/xiaodaozhi/xdstarter/issues/7) 跟踪。当前实现已扩展到真实目标、固定/取消固定及空布局，导入 UI 仍待开发。应用目标接入阶段的七套 CTest、23 项 GUI 检查，以及真实磁贴恢复、失效占位、取消最后一枚与空布局/light 新进程恢复保留为历史验证；后续 #14 桌面集成的十套 CTest、26 项 GUI、新进程恢复和各轮版本边界见[测试策略](testing.md)。本轮未修改布局 schema。

数据格式与兼容决定见 [ADR-0003](adr/0003-layout-snapshot.md)、[ADR-0004](adr/0004-application-catalog.md)；后者更新当前 schema、目标类型和默认布局，保留原有原子保存及版本保护。

## 数据职责与标识

`groupId`、`tileId` 与 `targetId` 在移动、尺寸切换和保存恢复中保持稳定。分组和磁贴快照是布局权威数据；目标描述与磁贴位置分离，同一 targetId 不因移动而变化。新增固定磁贴拥有独立 tileId，targetId 等于目录的稳定 appId；相同目标不会因重复点击固定而生成另一磁贴。

快捷方式 appId 为 `shortcut-` 加规范化绝对 `.lnk` 路径的 SHA-256，打包应用为 `packaged-` 加规范化 AUMID 的 SHA-256；规范化使用路径分隔符、路径清理及大小写折叠。不同路径的快捷方式可能带不同参数，保留各自身份，不按可执行文件合并。图标 key 与目标身份关联，实际 QImage 仅缓存在内存，不将位图、可执行文件参数或工作目录复制到快照。

应用目录可重新扫描，不能替代用户布局。恢复读取配置不会执行目标；平台在实际启动前再次检查描述、稳定 id 及可用性，不把外部 JSON 当作任意命令串。

## 当前 schemaVersion 2

配置为 UTF-8 JSON，根严格包含 `schemaVersion`、`targets`、`groups`、`preferences`。结构示例：

```json
{
  "schemaVersion": 2,
  "targets": [],
  "groups": [
    {
      "id": "default",
      "name": "常用应用",
      "tiles": []
    }
  ],
  "preferences": {"theme": "dark"}
}
```

上例是有效的空布局。固定后 targets 存放目标描述，tiles 存放 `{id, targetId, column, row, size}`。三种目标的字段如下；`id`、`type`、`name`、`symbol` 为必需，`iconKey` 为可选的字符串：

| type | 启动字段 | 行为 |
| --- | --- | --- |
| `shortcut` | `shortcutPath`：盘符或 UNC 绝对 `.lnk` 路径；不包含 `aumid` | 平台直接启动原快捷方式，保留其参数及工作目录 |
| `packaged` | `aumid`：受支持的 `packageFamily!application` 标识；不包含 `shortcutPath` | 平台通过应用激活接口启动 |
| `prototype` | 不包含启动路径或 AUMID | 保留旧样例，仅用于布局预览，不启动应用 |

路径拒绝协议/命令串、控制字符、Windows 非法路径字符和额外冒号；AUMID 仅接受字母、数字、点、下划线、连字符及分隔 package family/app 的单个 `!`，上限 256 字符。名称上限 512 字符，symbol 上限 16，iconKey 上限 512；平台启动层另检查目标身份和其支持的描述范围。图标失败或应用卸载不构成 JSON 结构损坏。

`LayoutStore::validate` 拒绝未知字段、错误数据类型、重复标识、无效 targetId 引用、非整数格坐标、越界与同组碰撞。尺寸仅接受 `small`、`standard`、`wide`，偏好目前仅接受 `dark`/`light` 主题；不暗示已实现跟随系统或窗口大小偏好。

限制为文件最多 1 MiB、32 组、512 个目标/磁贴、每组十列与最多 64 行；读取先限制字节数再解析，尺寸跨度也必须处于边界内。schema 2 至少保留一个分组，允许 targets 和所有分组的 tiles 为空，因此取消最后一枚磁贴仍可保存。schema 1 保持原约束，至少一个目标和一枚磁贴；不能将未校验的外部 JSON 直接绑定到 QML。

## schema 1 兼容与升级

旧 schema 1 只接受 `prototype`，继续严格验证后恢复原位置、尺寸和主题，不推断或执行真实应用。读取不立即改写文件；内存快照使用 schema 2，下一次用户编辑、固定或显式保存才升级主配置。升级沿用正常保存流程，将有效 schema 1 主文件的原始字节保留到 `.bak`，随后原子写入 schema 2。旧程序遇到 schema 2 应按原 ADR 进入未来版本只读，不能依靠忽略新字段来降级写回。

## 路径与隔离

普通启动通过 `QStandardPaths::AppLocalDataLocation` 获取当前用户目录，保存为 `layout.json`。应用身份固定为 organizationName `xiaodaozhi`、organizationDomain `github.com/xiaodaozhi`、applicationName `XDStarter`；公开配置不写开发者机器路径。程序安装目录和源码目录都不是默认用户数据位置。

`--layout-file <path>` 用于明确选择另一配置，验证时使用本项目 `build/` 下的隔离文件。`--smoke-test` 完全禁用布局读写和真实应用目录，即使指定 layout-file 也只使用内存样例；普通首次加载没有文件时使用空的“常用应用”分组，不在读取时创建配置。

## 保存、恢复与错误语义

1. 编辑和主题变更先生成完整内存快照并校验。controller 用 500 ms 单次计时器合并连续操作；仅保存已提交结果，不写拖拽预览帧。
2. 快照交给专用 QObject/QThread 后台保存；每次记录修订号，写入期间有新编辑时在完成后保存较新快照。UI 显示待保存、保存中、成功或失败状态，并提供“保存布局”重试；写盘失败不循环自动重试。
3. `QSaveFile` 禁止直接写回退，成功提交前保留原文件。`.bak` 保存已校验的有效状态；首次保存也建立可恢复备份，后续保存备份上一有效主配置。备份不能成功写入时拒绝覆盖当前主配置。相同路径由 QLockFile 防止写入交错；锁已占用则立即失败并提示重试，不提供多实例编辑冲突合并。
4. 主配置损坏时尝试有效 `.bak`；没有可用备份则显示默认布局并明确提示。读取不改写输入；随后确需保存时将损坏主文件另存为 `.corrupt-时间-随机标识`，无法保留则拒绝覆盖。有效备份不被损坏内容替换。
5. 识别到主配置或备份含较新 schema，或者任一文件超过 1 MiB 时，保留可用的有效主配置/备份或默认样例并进入只读。保存前还会重新检查主配置和备份的版本与大小，防止运行期间出现的新版本数据被覆盖；只读时布局编辑和主题变更禁用。
6. 正常退出会 flush 待保存快照，并等待后台任务结束后释放线程；失败保留之前的有效磁盘配置并报告原因。磁盘失败时内存编辑仍可见，不得显示成“已保存”。

固定与取消固定走相同的完整快照保存通道。取消固定仅移除磁贴和最后引用的目标描述，不删除系统快捷方式或卸载应用；磁贴移动、调整尺寸、图标加载与扫描刷新不改变启动参数。当前保存和恢复不执行目标。QSaveFile 原子替换、备份、损坏保留和未来版本保护分别测试，不把一次正常重启恢复等同于断电/所有文件系统故障保证。

## 失效目标与后续扩展

恢复时目录中不存在的固定目标通过后台可用性检查更新状态；启动前也会重新检查，失败保留窗口和位置并说明原因，允许取消固定。目标失效与布局损坏分别处理；当前尚未提供重新绑定目标 UI。目录不自动监视安装/卸载变化，可手工刷新。导入需校验版本、结构、数量和目标类型，在用户预览后替换，且不自动执行任何启动目标；当前没有导入 UI。

[Issue #8](https://github.com/xiaodaozhi/xdstarter/issues/8) 的搜索索引是可重建的进程内数据。controller 合并已发布目录与固定目标的名称／别名快照；快照变化后在独立 worker 重建有界索引，快照相同或仅图标／可用状态变化时不重建。当前没有持久化索引、文件系统增量监听或安装事件订阅；固定目标在目录中缺失时仍保留搜索入口及不可用说明。

查询、匹配结果、索引版本和浏览恢复位置不写入布局、偏好或日志；同一进程重新唤起保留查询，新进程从空查询开始。布局仍为 schemaVersion 2，已有保存、备份与未来版本保护不变。拼音采用固定 Unicode Unihan 17.0.0 的离线四字段派生表，来源、许可和边界见 [ADR-0010](adr/0010-local-application-search.md)、[依赖记录](dependencies.md)；不增加任意命令执行、用户配置网络同步或运行时下载。
