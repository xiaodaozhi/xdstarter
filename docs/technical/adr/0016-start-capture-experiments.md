# ADR-0016：开始按钮诊断与隔离接管对照原型

- 状态：接受实验边界，未选择新的产品接管方案
- 日期：2026-10-23
- 跟踪：[Issue #52](https://github.com/xiaodaozhi/xdstarter/issues/52)
- 承接：[ADR-0014](0014-start-click-and-adaptive-taskbar.md)

## 背景

用户反馈实际使用中仍会打开原生开始菜单。现行点资格要求 UIA 查询前后指针不变，点击点与查询点每轴最多相差 1 个物理像素，观察从查询开始至使用不超过 200 ms。快速移动后立即点击可能按设计放行。既有悬停后点击与窗口定位验收不证明快速输入的接管成功率。

低级 Hook 安装成功不能证明随后一直存活，UIA 订阅失败也不能继续呈现为正常接管。需要先分清放行、拥有按下后的取消、派发、显示失败与原生前台激活，随后再比较资格模型和输入路由。

## 决定

默认产品入口继续采用进程外 Hook 的点资格模式。诊断修复适用于默认入口；区域资格与进程内队列桥接都是明确选择的实验，不因编译或隔离测试通过自动升级为默认产品能力。

### 有界诊断

输入回调只更新有界内存计数和有限样本，不调用 UIA、等待 GUI、写盘或构造日志字符串。导出区分安装状态、当前资格、最近观察到的输入、已消费的按下/松开、完整手势派发及 host 的显示与原生前台确认。没有输入样本时，Hook 活性为未知；消息线程计时器响应也不是 Hook 仍存在的证明。

放行和取消保留结构化原因。查询端记录 UIA 耗时、资格年龄、点差、代次失效来源和订阅 HRESULT。订阅失败取消资格并报告错误，重新启用时重建所需资源。所有状态仍受 session generation 约束，旧会话不能重新唤起窗口。

`--start-capture-diagnostics <path>` 由 GUI 定时器原子覆盖同一诊断文件，退出时补写；没有此选项时不自动创建诊断文件。诊断不包含应用目录、完整输入轨迹或输入文本。显式选项不通过第二实例 IPC 转交给已有进程，必须启动对应的新进程才能改变实验设置。

### A：外部区域资格原型

`--start-capture-mode point` 为默认；`area-cache` 显式选择实验。区域资格必须来自 UIA 唯一 Start 按钮与真实 Explorer 任务栏身份，不能由屏幕角落、按钮近似坐标或上一次窗口位置推断。区域标记、短租约、失效代次与每次原生窗口/进程/矩形/DPI/命中复核共同约束许可。UIA 和输入仍不是原子事务。

改进的目的在于验证区域缓存能否减少快速移入的资格缺口，同时测量误吞邻近项的风险。不能仅扩大旧点容差或延长过期时间。完整手势、注入输入放行、修饰键/右键放行、拖出取消及已拥有释放的成对消费继续有效。

当前原型只预热真实指针所在显示器的任务栏，100 ms 内复用元素，按最初唯一元素验证时间计算 200 ms 租约。跨屏后立即点击仍可能遇到首次查询空窗。区域模式把 UIA 属性订阅限制到 Start 本体、结构订阅限制到其子树，并在同一任务栏的按钮重建后重新订阅；点模式保留原订阅范围作为对照。

### B：独立进程内队列桥接原型

单独构建无 Qt 的桥接 DLL、受控 Win32 输入宿主和独立 Qt 控制器。通过指定线程的 `WH_GETMESSAGE` 让系统在受控宿主加载 DLL；仅在 `PM_REMOVE` 阶段处理资格匹配的队列消息。桥接内部不加载 QML、不扫描目录、不执行应用或进行阻塞 IPC；完整手势通过有界队列交给 worker，再发往独立进程。

会话绑定目标进程、创建时间、GUI 线程、窗口代次、模块身份、位数和随机 nonce。IPC 仅限本地当前用户；未连接、过期或不支持的目标对新手势放行。停用先停止接收新按下，再排空已拥有释放；卸载必须等待回调及 worker 安全结束，超时不能宣称卸载成功。

该原型限定在自有 fixture 白名单，拒绝 Explorer。它证明 DLL、队列与 IPC 边界能运行，不证明现代任务栏所有鼠标、触控、键盘和 XAML 输入都经过该队列。现代 InputSite 的共享窗口过程适配、版本门槛及实际 Explorer 接管仍需单独研究和验收。本轮不采用跨进程 `SetWindowSubclass`，不安装系统范围 Hook，不替换系统文件。

本机传输诊断发现手工 `PostMessage(WM_POINTER*)` 返回 `ERROR_INVALID_MESSAGE`（1002），两次消息均未进入 Hook；手工消息也未保留触控兼容鼠标签名。不能以原生计数为零证明输入已被消费。因此 B 本轮仅接管受控宿主的鼠标队列，真实 `WM_POINTER` 通路全部原样放行，未采纳触控拦截。指针与兼容鼠标状态检查改为明确的受控仿真帧，共用规范化手势逻辑，且需要会话显式启用 `enableEmulatedFrames`，默认关闭。仿真帧检查不是 Windows 指针路由验收。

现有产品“不注入 Explorer”约定继续有效。用户授权的本轮进程内对照实验只在上述受控宿主中加载 DLL；将来要进入 Explorer，必须更新目标范围、恢复策略和实际验收记录。不能仅移除白名单使实验成为产品。

## 验证与取舍

纯状态机与故障注入覆盖资格、放行原因、完整手势及诊断边界；真实 Windows 自有进程覆盖 DLL 加载、消息投递、IPC 失联、心跳过期、停用和窗口重建。实验默认不参与产品构建；CI 显式构建并运行受控宿主集成检查。

真正的 A/B 稳定性结论需要同一环境、相同输入矩阵：零停留移入即点、微动、连点、拖出、右键/Win+X、四边与双对齐、多屏/DPI、自动隐藏、Explorer 重启和睡眠。分别统计原生漏出、双弹、无响应、重复切换、误吞邻近项与恢复失败。合成消息与纯状态机结果不能替代物理输入验收，也不能由一次 Hook 安装成功推断长期健康。
