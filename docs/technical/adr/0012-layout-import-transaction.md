# ADR-0012：布局导入预览与替换事务

- 日期：2026-10-21
- 状态：采用；构建与实际窗口验收分别记录
- 关联：[Issue #10](https://github.com/xiaodaozhi/xdstarter/issues/10)
- 延续：[ADR-0003](0003-layout-snapshot.md)、[ADR-0011](0011-tile-display-names.md)

## 背景

已有保存层支持严格版本校验、原子主文件替换、上一有效配置备份和未来版本只读保护。启动恢复允许主文件失败后读取 `.bak`，但用户选择导入的文件必须单独校验，不能悄悄改为导入同名备份。已有自动保存也不能在导入成功后把旧内存快照写回来。

## 决定

1. “更多”菜单提供“导入布局…”及“恢复上一份布局…”。使用 Qt 6.8.2 公共 `QtQuick.Dialogs.FileDialog`，强制 `DontUseNativeDialog` 的 Qt Quick 实现并设 `ReadOnly`，不依赖 Widgets、私有 API 或原生 COM 对话框焦点。确认界面使用窗口内 `Popup.Item`；文件选择及确认均参与内部弹层、Esc 和收起清理。实际 Windows 焦点归属仍以本轮真机验收为准。
2. 只接受文件 URL。后台直接打开所选文件，最多读取 1 MiB 加一个超限哨兵字节；拒绝无法读取、非 JSON 对象、过大、未来版本及结构／引用／几何无效的文件。严格复用 `LayoutStore::validate`，不调用具有自动备份回退语义的 `load`。来源失败不使当前合法配置只读。
3. 合法 schema 1／2／3 通过临时 `PrototypeService::restoreSnapshot` 规范化为当前 schema 3，保留目标描述与标识。预览缓存经过验证的不可变快照，单行显示文件名（过长中间省略）、最多两行显示目录，并通过纯文本提示和辅助说明提供完整来源；同格式仅显示版本号，旧格式才显示迁移箭头，另列分组／磁贴／目标数和主题。所有外部文字按 PlainText 呈现，包含导入目标的 symbol；其长文字限制在原有 28／36 DIP 图标槽，不扩大磁贴。确认导入的是这份内容，之后文件替换不改变预览结果。不执行目标，也不在预览阶段注册应用或提取图标。
4. 预览绑定当前布局修订号。已提交编辑或主题变更使读取中的或已完成的预览失效；取消使后台旧代次结果无效。确认时再次检查只读、持久化能力、代次及修订。样例模式和无保存 worker 的 controller 同样拒绝导入，不仅依靠按钮禁用。
5. 确认后停止自动保存计时，并在现有保存 worker 队列中，确有未保存修订时先保存当前合法布局，再保存导入快照；已保存状态直接保存导入快照，保留旧主文件的原始字节备份。期间拒绝所有布局及主题修改，不新建保存线程。先前排队的自动保存先完成，worker 再复核实际已保存修订，避免重复 flush；其旧完成回调不能重启计时或覆盖事务状态。导入保存成功后才发布新内存布局与主题、刷新目录元数据和搜索，关闭编辑并清空查询。失败不发布导入布局。
6. 保存当前编辑是正常保存，可能更新主文件；如果随后导入写入失败，当前布局仍保留，已保存的此前编辑继续有效，不能笼统宣称磁盘完全没有变化。两个步骤复用 `LayoutStore::save` 的版本重读、锁、备份失败拒绝覆盖和 `QSaveFile`。运行中目的配置出现未来版本／超大文件时进入只读。主文件替换原子性不等于主文件与备份跨文件事务，也不保证所有文件系统断电场景。
7. 退出 flush 先对同一 worker 排队建立完成屏障，消费正在执行的导入结果，再决定是否保存当前内存；不会在导入落盘但 GUI 回调尚未处理时用旧内存覆盖它。读取未确认时退出只取消预览，并正常保存此前已提交编辑。
8. “恢复上一份布局…”严格读取当前路径的 `.bak`，走同一预览与替换事务；即使第一步保存改变了备份内容，确认对象仍为原预览快照。成功后的备份保存替换前的有效当前布局；没有未保存编辑时保留主文件原字节，有待保存编辑时保留已 flush 状态，允许再次预览恢复。

## 验证边界

服务测试覆盖严格所选文件语义、版本／大小／引用／几何边界、旧版本规范化、写入次序和失败不发布。GUI 测试覆盖预览计数、取消、过期、只读及样例拒绝、修改门控、文件变化、重启恢复和退出屏障。深浅色文件选择与确认、内部焦点、真实外部收起、托盘唤回和独立产品重启需另外记录 Windows 实测证据；离屏检查不能替代真机验收。
