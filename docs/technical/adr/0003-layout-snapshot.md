# ADR-0003：原型布局快照与版本保护

日期：2026-10-20。状态：已接受，依据项目所有者要求实现磁贴拖拽、三档尺寸切换和布局保存恢复；对应 [#9](https://github.com/xiaodaozhi/xdstarter/issues/9)、[#10](https://github.com/xiaodaozhi/xdstarter/issues/10)。

## 背景

原型已经使用稳定的样例磁贴与共享整数网格，需要将组内/跨组移动、尺寸和深浅主题跨进程恢复。当前没有真实应用目录、启动服务、固定/取消固定、分组管理或导入 UI。持久化必须区分原型样例与未来实际启动目标，避免将未来配置交给旧版本覆盖。

## 决定

- 使用本地 UTF-8 JSON `schemaVersion: 1`，严格限定根结构、目标、分组、磁贴与主题字段，未知字段或类型不匹配拒绝。组与磁贴保存稳定 id、targetId、整数 column/row、small/standard/wide，不保存显示像素宽高。
- 当前 target 仅接受 `type: prototype`，名称和通用 symbol 负责原型呈现，不执行命令、文件路径或 AUMID。后续真实目标与导入能力需要明确的数据兼容策略，不能把这份原型格式当作通用启动描述。
- 默认路径由 QStandardPaths::AppLocalDataLocation 决定，产品身份保持固定；`--layout-file` 提供隔离配置，`--smoke-test` 完全禁用布局 IO。首次无文件时使用明确的原型默认样例，读取阶段不写盘。
- C++ 服务完成落点校验、移动/跨组和尺寸变更，先校验再修改内存；预览与提交使用同一几何规则。QML 只承担呈现和输入反馈，不直接写 JSON。
- controller 对已提交布局和主题快照合并保存，500 ms 后通过专用 QObject/QThread 写盘；用修订号区分写入中和后续编辑，退出 flush 并等待后台结束。保存失败向 UI 返回明确状态，允许重试。
- LayoutStore 使用 QSaveFile 原子提交，禁止直接写回退，保存前严格校验完整快照。首次保存建立有效 `.bak`，后续保留上一有效主配置；备份失败即拒绝覆盖主配置。QLockFile 阻止同路径 writer 交错，锁占用时明确失败，不实现多实例冲突合并。
- 主配置损坏时尝试有效备份；没有有效数据时显示默认样例并提示。读取保留原文件，后续保存前另存损坏输入；不能保留损坏文件时拒绝覆盖。
- 主配置或备份包含较新 schema，或者任一文件超过读取上限时，进入只读并保留输入；保存前再次核对版本和大小。当前约束最多 1 MiB、32 组、512 个目标/磁贴、十列与64行，防止无界读取和布局数据。

## 取舍与影响

本阶段只需完整快照，JSON 配合 Qt 现有文件 API 足以表达配置与恢复，不引入数据库或新的运行依赖。移动的内存原子性与磁盘原子替换分别负责用户布局和失败恢复；多文件备份步骤不宣称为跨文件系统事务，也不保证所有断电/文件系统异常。

QLockFile 保护保存步骤，不解决两个长期运行实例的编辑版本冲突；单实例与配置导入另行设计。旧版本不得通过忽略字段的方式读取未来启动目标，新增目标类型或结构应先更新 schema/迁移与回归策略。部署或卸载不能顺带覆盖用户布局。

## 验证与后续

针对正常重启、跨组/尺寸/主题恢复、损坏主配置、首次备份、备份失败、写入冲突、较新版本、超限和退出前保存分别验证。GUI 测试使用隔离临时文件，产品实际窗口使用 `--layout-file`，证据与未验收边界见[测试策略](../testing.md)。

完整字段及错误语义见[数据与持久化](../data-persistence.md)，几何与输入规则见[磁贴布局](../tile-layout.md)。真实应用目标、固定/取消固定、分组管理、导入 UI 和系统接管不因本 ADR 被标记为完成。
