# ADR-0010：离线应用名称与拼音搜索

- 日期：2026-10-21
- 状态：采用；实际构建、窗口交互与性能证据见[测试策略](../testing.md)
- 关联：[Issue #8](https://github.com/xiaodaozhi/xdstarter/issues/8)、PRD-006、PRD-012
- 延续：[ADR-0004](0004-application-catalog.md) 的稳定目标、真实目录与受控启动边界

## 背景

原型已有真实应用目录、固定磁贴及后台启动，但需要在同一入口通过名称、英文、拼音或首字母快速查找应用。搜索范围包含已安装目录与已固定的快捷目标；相同目标可能同时出现目录名称与磁贴名称。Shell 枚举、索引构建及多音匹配不能进入 QML 或输入接管回调，也不能把键入的查询变成任意命令。

现有无 Qt 的 `core` 面向几何与布局。搜索需要 Unicode NFKC、大小写折叠、UTF-16／Unicode 标量转换及跨线程值传递，直接复用 Qt Core 可减少另一套文本实现。汉字读音还需要固定来源、许可、可复核生成方式与明确的多音边界。

## 决定

1. 在 `services` 增加使用 Qt Core 值类型的 `SearchIndex` 与 `SearchService`，不将其放入无 Qt 的 `xdstarter_core`，也不依赖 Win32。`MenuController` 在 GUI 组装目录和固定目标的值快照、映射结果呈现；索引构建与查询在专用 QObject / QThread worker。
2. 按稳定 targetId 去重。目录名称优先作为显示名称，磁贴名称作为别名；目录没有记录的固定目标仍可索引。只传 id、名称、别名，不向算法传 Shell 对象、目标路径或启动参数。快照未变时不重新构建；图标及可用性使用现有缓存更新。
3. 一次只派发一个后台任务，GUI 保留最新查询与最新目录，分别用查询代次和目录修订校验返回。查询改变即失效旧结果；旧任务返回后转向最新输入，不把每次键入排成无限队列。正在执行的查询不被强制终止；退出请求中断并等待 worker 结束。
4. 原名称及别名统一 NFKC、casefold 和有界截断。排序按完整匹配、前缀、包含、全拼、首字母依次降低优先级，同档按规范化显示名称、稳定 id 排列。仅发布前 100 个目标，并保留匹配总数；同目标的多个名称不产生重复行。
5. 使用固定 Unicode Unihan 17.0.0 四字段派生表，不引入拼音运行库或网络服务。以 Unicode 标量查找逐字读音，覆盖多音全拼及首字母；保留英文片段。用每个字音之后的可达 KMP 状态集合匹配，不构造或截断多音读法的笛卡尔积。
6. 搜索结果启动只接受当前有效结果中的受控 id。沿既有 `ApplicationCatalog` 再检查可用性并调用平台启动；不可用、已过期、忙碌或样例结果不启动。查询不作为路径、URI、脚本或 Shell 命令，也不触发网络请求。

## 输入、匹配与容量

索引最多读取 8192 条输入目标记录，按 id 合并；每个合并目标最多 16 个显示名称／别名，每个名称最多 256 个 UTF-16 代码单元。有效查询最多 128 个 UTF-16 代码单元，原输入与 NFKC / casefold 后均有界截断，避免把代理对截开。结果显示前 100 项；这些容量限制没有承诺所有上限组合都满足搜索响应目标。

拼音查询去声调，`ü`、其带声调形式、`u:` 与 `v` 使用同一键；源数据先转换 `ü → v` 再去声调，避免折叠成 `u`。名称保留字面符号匹配，拼音路径可略过空白与标点；查询中的空白、单引号与连字符可作为拼音分隔。纯符号不会因为拼音键为空而匹配全部结果。无法匹配字音或拉丁转写的字符形成路径断点，不把断点两侧无关片段拼成结果。

英文与中文混合名称保留英文片段，例如 `Windows 终端` 可匹配 `windowszhongduan`、`windows zd`。逐字多音同时保留候选，因此 `重庆银行` 可匹配常用读法，也可能接受不符合当前词义的读音组合。没有词级断词、上下文消歧、输入纠错或完整汉语覆盖保证。

状态集合使多音展开有界，但最坏工作量仍包含查询长度、别名数、每字符候选数及候选长度；不能把它表述为与这些因素无关的单串线性 KMP。PRD-012 的 P95 目标须用明确设备、固定参考数据集和实际计时验证，索引查询计时与整个界面到结果呈现的耗时分别记录。

## 窗口与键盘契约

搜索框常驻顶部，Ctrl+F 聚焦并选择已有文本；重新唤起聚焦搜索框，当前进程的查询保持。输入法预编辑不查询，预编辑期间 Enter 不启动、Esc 不清空或收起，提交文字后再更新。向下键从搜索框进入结果，结果上下键选择，首项向上返回输入框，Enter 启动当前可用项。

查询非空时切换正文，保留浏览视图、应用列表选中项与滚动、磁贴区横纵滚动；清空后恢复这些位置。搜索时不修改磁贴布局或退出已有编辑状态。Esc 先由当前子菜单处理或取消拖拽，再清空搜索、退出编辑，最后收起主窗口；直接收起仍保留查询与布局，不保存临时弹层或拖拽。

忙碌与无结果状态分别说明，目录扫描使用已有快照并提示更新；刷新失败保留旧目录。未固定且已离开目录的目标从索引移除，固定但失效的目标保留并说明不可用。图标按每 id 版本更新，图标失败保留占位。查询只存于进程内，不写入布局、日志或偏好；重启从空查询开始，不改变 schemaVersion 2。

schema 3 的每磁贴显示名称扩展由 [ADR-0011](0011-tile-display-names.md) 定义：结果仍优先目录名称，原目标名称和同目标所有有效覆盖均作为别名；恢复原名或移除覆盖后重建当前名称快照，不保留被删除的历史别名。普通每目标16名称上限保持，磁贴覆盖使用全索引合计512条的独立有界预算。

## 数据来源与许可

固定来源为 [Unicode Unihan 17.0.0 官方包](https://www.unicode.org/Public/17.0.0/ucd/Unihan.zip)，属性含义参照对应 [UAX #38 修订 39](https://www.unicode.org/reports/tr38/tr38-39.html)。按 `kMandarin`、`kTGHZ2013`、`kXHC1983`、`kHanyuPinyin` 顺序取并集，丢弃字典位置及声调，稳定去重。四字段补充简体常见多音字：`乐 le/yue`、`长 zhang/chang`、`重 zhong/chong`、`行 xing/hang`。没有加入其他 Unihan 读音属性、简繁变体传播或词级词库。

规范表包含 44,359 个码点、52,982 个字音，单字最多 8 音、每音最多 6 个 ASCII 字母。每个 C++ 记录使用短字符串，避免 MSVC 超长拼接字面量；`pinyinReadings(char32_t)` 对未知标量返回空列表，原名称仍可字面匹配。

官方源 ZIP 的本地计算 SHA256、提取文本哈希、转换方式及输出统计保存在 [manifest](../../../third_party/unicode/manifest.json)。原始 ZIP 留在构建缓存，不提交；规范 TSV、C++ 表、来源说明及完整 [Unicode License v3](../../../third_party/unicode/LICENSE.txt) 一同入库。生成器只接受明确指定且哈希一致的本地源，或使用已入库 TSV 离线重建；检查器核对输出、许可及常见多音，均不下载数据。普通构建直接编译表，无需生成期或运行期网络。

[Unicode 数据使用条款](https://www.unicode.org/copyright.html)指定 Unicode License v3；派生分发需在副本或随附文档保留版权与许可通知。未来二进制／安装包必须带上这些材料。该决定不确定项目自身许可证，不替代 Qt 或整体发行审查；详见[数据来源说明](../../../third_party/unicode/README.md)与[许可治理](../../governance/licensing.md)。

## 验证边界

单元检查覆盖名称及多音匹配、规范化、未知字符断点、稳定去重排序、容量、旧查询／目录返回与线程退出；controller / QML 检查覆盖受控启动、输入法预编辑、方向键、清空与浏览位置、Esc 顺序及每 id 图标更新。参考数据集计时是专门运行的测量入口，不能只因构建成功而声明性能达标。

真实 Windows 应用目录、物理输入法、图标及启动、托盘重新唤起与重启状态应按当前二进制分别验收；模拟平台和合成 IME 事件不能替代实际系统兼容验证。实际完成范围、未测环境和性能数据统一在[测试策略](../testing.md)及 [Issue #8](https://github.com/xiaodaozhi/xdstarter/issues/8)记录，本 ADR 不声明任何未运行的测试已经通过。
