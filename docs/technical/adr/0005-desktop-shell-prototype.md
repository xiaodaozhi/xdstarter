# ADR-0005：先接入可恢复的普通窗口桌面集成

- 日期：2026-10-20
- 状态：已采用；实际兼容范围以验证记录为准
- 关联：[Issue #14](https://github.com/xiaodaozhi/xdstarter/issues/14)、[设计素材 #13](https://github.com/xiaodaozhi/xdstarter/issues/13)、[系统接管研究 #6](https://github.com/xiaodaozhi/xdstarter/issues/6)

## 背景

设计修订 2.1 已交付快捷栏、圆形头像与软件图标。运行时已有应用目录、启动与布局保存，成功启动后的窗口收起需要可靠的再次打开入口。开始按钮左对齐也需要真实桌面几何，不能将设计稿固定坐标复制到窗口位置。

系统 Win 键/开始按钮接管及 DWM 材料尚未完成兼容研究，当前素材接入需要保持原生系统行为，并能独立验证普通窗口生命周期。

## 决定

1. 保持 Qt Quick / QML 与 C++。快捷栏使用已交付的 qrc SVG，Windows EXE 编入 ICO，应用与窗口使用多尺寸 `QIcon`。
2. 将桌面动作与只读 UIA 查询放入独立 `DesktopPlatform`，由 `DesktopShellService` 专用 worker 串行执行。动作仅接受文档、下载、设置和账户四项白名单，后两项使用固定系统 URI；不提供任意命令入口，系统电源操作未启用。
3. 用 `DesktopWindowHost` 统一普通窗口、异步定位与恢复入口。托盘采用 `Shell_NotifyIcon`，不引入 Widgets；原生通知排队给 Qt，停止或重建会话后旧回调失效。
4. 托盘可用时保持进程常驻并允许重新显示；不可用时保留普通窗口关闭退出行为。应用或快捷动作成功收起后，无托盘则最小化到任务栏，避免隐藏且不可恢复。明确退出入口保存布局并清理资源。
5. 每次用户唤起都只读识别真实 Explorer 任务栏中的唯一 UIA StartButton，检查类型、进程与物理边界；查询代次阻止旧结果作用于新窗口状态。GUI 仅执行短时本进程窗口定位，补偿 DWM 可见边框并夹限工作区。识别失败明确回退，异步结果不重新激活已失去焦点的窗口。

## 影响与验证边界

桌面动作与 UIA 的 Shell/COM 调用不进入 GUI 或原生消息回调，测试可注入假平台而不打开用户目录或系统设置。快捷栏与托盘不改变原生开始菜单，也不依赖持久化屏幕像素坐标；本轮没有修改布局 schema。

本轮仍是带系统边框的普通窗口，没有输入 Hook、无边框弹层、DWM 背景材料或外部点击关闭。Explorer 重启重注册已有代码，自动隐藏任务栏、混合 DPI 跨屏及实际 Explorer 重启仍需专门验证。普通窗口结果不作为 #6 完成依据。
