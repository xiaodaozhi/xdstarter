# ADR-0021：布局文件选择器的请求生命周期

日期：2026-10-30。状态：实现及验证中。跟踪 [#88](https://github.com/xiaodaozhi/xdstarter/issues/88)。

## 背景

Qt 6.8.2 的 Windows 原生文件选择器在独立线程执行 `IFileDialog::Show`。快速关闭时，若线程尚未建立原生窗口，Qt 的关闭请求可能没有目标；下一次打开可能遇到线程清理超时，甚至留下迟到窗口。延时、屏蔽日志或按窗口标题关闭都不能可靠处理这一交错。

## 决定

- Qt Quick / QML 保持界面与导入预览，Windows 图形平台将布局文件选择交给同一 `xdstarter.exe` 的内部辅助模式。辅助模式在初始化 Qt GUI、单实例、托盘和系统接管之前执行，仅创建系统 `IFileOpenDialog`。离屏及其他 Qt 平台保留 Qt Quick 文件选择器作为测试回退。
- 每个请求使用单独的辅助进程、私有 kill-on-close 作业及仅继承必要句柄的有界共享内存；进程和主窗口的身份均通过实际句柄及 PID 校验。请求结束前不会启动后续请求；取消与退出不等待 COM 返回。辅助进程退出后才恢复原本启用的 owner，并开始仍有效的后续请求。
- GUI 线程状态机为请求分配单调代次；取消、关闭窗口及退出后的迟到结果不得发布。主窗口对外部进程的焦点例外只针对已登记的活动辅助进程，必须同时满足存活进程句柄、PID、准确 owner 链和当前前台窗口，不能只靠标题或 PID。
- 辅助进程与主程序共用既有 EXE，不增加发行文件或更改布局格式；选中文件仍经过原有导入验证。辅助进程启动或执行失败时，主界面给出可见错误。

## 验证边界

核心状态机测试覆盖取消后立即重开、旧结果丢弃、退出和未完成请求上限。一次性 hosted Windows 上分别检查快速取消、原生窗口出现前关闭、窗口出现后关闭、重新打开和通过独立可终止 UI Automation 进程选择文件。日志必须保留原始 Qt 严重消息以及进程/owner 身份；有限事件观察和轮询不能证明没有任何短暂画面。夹具或 CI 通过不替代干净 Windows 11 安装、真实驱动与实际用户桌面焦点验收。
