# ADR-0015：动态磁贴列数与布局格式4

- 日期：2026-10-23
- 状态：采用；实现检查与Windows实际验收以[测试策略](../testing.md)和Issue证据为准
- 关联：[Issue #48](https://github.com/xiaodaozhi/xdstarter/issues/48)、PRD-003、PRD-005、PRD-007
- 延续：[ADR-0011](0011-tile-display-names.md)、[ADR-0013](0013-resident-editable-menu.md)、[ADR-0014](0014-start-click-and-adaptive-taskbar.md)

本 ADR 保留当时的格式4决定。当前格式已升级为 schema5，主题偏好与兼容规则见 [ADR-0018](0018-system-theme-preference.md)；本 ADR 的列数和几何规则继续适用。

## 背景

原先视口随窗口变化，但每组始终只有10个可用格列，标题与管理按钮的右缘也固定在552 DIP。用户已明确要求可用磁贴列数随窗口宽度变化，仅扩大呈现空白不能满足这一语义。旧schema3严格校验10列和根字段，直接放宽同版本坐标会使旧程序将新布局误判为损坏输入。

微软公开资料支持Windows10可拖顶部／侧边调整菜单大小，也公开了布局中的组列组织；没有公开本次能核实的交互吸附阈值算法。依据与未选的576 DIP整组分栏方案保留于[研究记录](../research/menu-layout-followup-48.md)。

## 决定

1. 当前写入schemaVersion4，新增必需根整数 `gridColumns`，范围4到64，所有分组共用。最小4列保证宽磁贴可容纳，最大64列保证占位与试探有界；每组64行、32组、总512磁贴／目标及1 MiB限制不变。48 DIP小格、8 DIP间隙和三档跨度保持共享来源，不保存像素几何。
2. 严格读取schema1/2/3，保持旧版10列约束并拒绝新根字段。旧布局只在内存升级为4；读取不改写原文件。首次已提交编辑或保存仍通过原子保存通道，将旧主文件原始字节保留到备份。旧程序按未来版本只读保护4；当前程序对更高版本的保护不变。
3. 列预算按实际磁贴可用宽度计算：`floor((availableWidth + gap) / pitch)`，夹限4到64。分组外层与标题占满视口，实体网格宽度为 `columns × pitch − gap`。窗口宽度变化采用500 ms单次去抖，不逐帧生成磁盘写入；导入提交与拖动期间延后提交，尺寸变化取消旧拖放预览。
4. 扩列保留原位；缩列先保留所有仍可容纳且不冲突的原位，再按旧行、列稳定排序，把越界者放入从前到后的合法空位。对全部分组规划完整副本；空间不足时列数与所有磁贴整次不改。成功后一次发布快照和动画几何，保存列数与新坐标，不改变ID、目标描述、显示名称或磁贴尺寸。
5. 原生横向缩放按56 DIP步距吸附，整窗档位包含固定分区、正文边距、实际滚动条预留及透明阴影。只从当前最小尺寸与工作区上限之间选最近合法档位，平局偏小；没有合法档位时保留已夹限的提议矩形。保持非拖动边与纵向几何，最终仍由平台工作区约束复核。该算法是XDStarter规则，不宣称精确复刻Windows10未公开的内部行为。

## 验证与影响

核心检查覆盖4到64列的实体几何、宽磁贴边界、完整新增格列阈值和非法宽度。领域检查覆盖扩列保位、缩列稳定重排、超旧边界的实际移动、最大列／行、目标与ID保持、空间不足整次回滚及恢复往返。存储检查覆盖旧1/2/3字段与10列边界不变、必需列数及其类型、格式3精确字节备份、格式4宽布局原子保存。

吸附纯函数检查五档DPI、正负坐标、左右与角部、最小／最大列、阈值平局、屏幕上限优先及无可用档位；Windows自有HWND测试复核实际sizing消息，GUI检查宽缩列、焦点可达和保存恢复。测试声明不表示本轮所有检查已经通过，也不替代真实桌面、混合DPI与系统恢复验收。旧版本的证据保持原版本身份。

新格式不增加任意启动命令、网络同步或新运行依赖。普通查询、滚动与窗口像素宽高不持久化；窗口重开仍按当前屏幕、任务栏方向与对齐定位，列数根据当前可用空间有界更新。
