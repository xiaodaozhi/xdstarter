# Windows 系统集成

状态：高优先级原型研究，尚未验证任何 Windows 构建支持。对应 PRD-001、PRD-010、PRD-011。

## 实现边界

独立普通用户桌面程序，保留 Explorer，不向其注入代码，不替换系统文件。集成模块通过 Win32/COM 实现材料、窗口位置、托盘、应用目录与输入事件。使用 QGuiApplication，托盘优先封装 Shell_NotifyIcon，避免为了单一托盘功能引入整个 Widgets UI。

## 唤起与焦点

Win 键状态跟踪与开始按钮识别独立于 QML。平台模块发出 toggle 请求，由主线程统一处理显示器、窗口激活和搜索焦点。重复请求去抖，子菜单、拖拽和焦点变化不误触发关闭。

单独按下并释放 Win 键切换菜单是目标行为；Win+E/R/L/数字、左右 Win 键、按住/重复按键、其他程序快捷键都必须保留并验证。开始按钮左键接管、右键系统菜单分别测试，不能仅根据屏幕固定坐标猜测按钮位置。

如使用低级输入 Hook，放在带消息循环的专用线程；回调只更新最小状态和派发事件，不执行 COM 查询、磁盘操作或 QML 调用。超时、Hook 丢失、Explorer 重启后应能检测异常并停止接管。

## 开始按钮与兼容策略

原型研究 UI Automation 等识别方式，验证任务栏居中/左对齐、自动隐藏、副屏和语言差异。先探测支持条件再启用接管，不以关闭原生菜单后重开自定义窗口的闪烁方案作为验收通过。

对不支持的系统组合保留原生行为，托盘明确提示接管不可用。安全桌面、锁屏、UAC 等系统隔离场景不接管。

## 窗口与材料

在 Qt Quick 的 Windows 原生窗口句柄上评估 DWM 背景材料、透明合成、圆角、阴影与显示动画。验证 Qt 渲染后端与原生材料组合，材料不可用或系统关闭透明时采用主题纯色。该效果需要真机确认，不能用截图替代验证。

位置以目标显示器工作区和任务栏位置为依据。每次唤起重新校验工作区，处理 DPI、任务栏自动隐藏和分辨率变化。跨屏使用单一坐标转换边界。

## 应用与恢复

读取当前用户及公共开始菜单、补充打包应用。保持应用解析与启动接口可替换，使用系统启动 API 处理快捷方式/AUMID。用户操作所需的管理员启动单独请求系统提升，主进程不长期提升权限。

托盘始终提供暂停接管、恢复原生菜单和退出。异常退出时由进程退出释放 Hook；重启不自动恢复已判定失败的接管状态。卸载检查开机启动项和托盘资源清理。

## 必须产出的验证记录

原型 Issue 记录 Windows 版本/构建、架构、任务栏设置、DPI、Qt 版本、渲染后端、通过/失败用例与恢复步骤。只有记录通过的组合进入支持矩阵。
