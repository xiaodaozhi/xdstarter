# 测试策略与验收

## Windows 打包工程验证

[#64](https://github.com/xiaodaozhi/xdstarter/issues/64) 增加路径／清单、供应方哈希、普通与延迟 DLL 导入、插件依赖、缺失 CRT、测试依赖隔离及 ZIP 字节回归。installation-guard 原生测试用独立进程验证安装／运行互斥及正常释放；Qt 翻译测试分别加载 SDK 与实际部署目录。入口与工件见[发行流程](release.md)。

[#66](https://github.com/xiaodaozhi/xdstarter/issues/66) 排除软件 OpenGL DLL，CI 清除副本的 SDK 搜索路径并确认宿主系统目录也不含该 DLL，再验证 Qt Quick 软件、Windows D3D11 与显式选择的 WARP 软件设备；记录选中适配器，Test／offscreen 只加入副本。强制 WARP 不模拟硬件故障，也不证明自动回退。一次性 hosted Server 夹具与实际产品分别记录哈希，夹具只降低 OS 门槛，不计作干净 Windows 11 验收。运行结果、失败和剩余项在 #66／#36 与 CI 工件登记；本节不宣称尚未运行的检查通过。

[#68](https://github.com/xiaodaozhi/xdstarter/issues/68) 增加两层隔离回归：假托盘和假输入接管在图形错误退出时检查停止顺序；Windows 测试在临时副本中以测试 DLL 模拟 D3D11 设备创建失败，覆盖正常、代理直通、硬件失败后的自动 WARP、硬件与 WARP 均失败及延迟失败。发行运行目录再执行同样检查，不把测试代理或系统 D3D11 副本打入发行包。默认适配器已经是软件设备时，硬件回退用例记录跳过；设备创建故障注入不代表真实驱动损坏、运行中设备丢失或干净 Windows 11 验收。

[#70](https://github.com/xiaodaozhi/xdstarter/issues/70) 使用注入的提示接口检查成功、系统提示失败后的回退、全部失败和看门狗启动失败；在独立测试进程模拟系统调用或回退提示卡住，验证看门狗结束该进程。假托盘／假接管测试检查释放后才启动提示、重复故障只尝试一次、事件循环前失败与冒烟模式不显示提示。D3D11 夹具要求冒烟测试不启动辅助进程；仅在一次性 hosted runner 的常规 CTest 和发行运行目录验证中启用常驻用例，先观察开始按钮接管与 Hook 已启用，再检查真实故障恰好启动一个提示进程、退出后停止接管，并等待该进程结束后清理隔离副本。CI 即使其他 CTest 失败也上传该用例的独立证据。本地运行不启用真实接管。系统提示是否在当前交互桌面实际可见另需原生会话验证；单元测试和 hosted 结果不代表完整 Windows 11 系统入口验收。

[#72](https://github.com/xiaodaozhi/xdstarter/issues/72) 的布局导入键盘测试在状态变化时记录提交中、确认按钮禁用与透明度，并在按键前检查焦点；快速完成的测试行强制后台提交在按键函数返回前完成，仍要求观察到提交中状态及最终布局。Windows hosted CTest 单独运行原生 D3D11 版本并上传日志，发行目录仍保留原有验证；Qt 系统文件选择器线程清理警告的原因及真实 Windows 11 行为另行跟踪，不能以该测试代替。

## 当前自动检查

`python3 scripts/check_repository.py` 检查本地文档/图片链接、JSON/SVG/PNG 基本有效性、当前设计尺寸、Logo 透明通道及 SVG 网格几何。该检查不运行 Qt，也不代表 Windows 原型通过。

GitHub Actions 在 push/PR 上运行相同检查。设计重建后应目视查看 PNG，核对字体、应用图标、长名称、间隙及辅助功能信息的表达。

快捷栏实际验证选择文档等已知入口，检查新系统窗口打开、产品收起及托盘恢复；不批量打开用户目录或设置。托盘文字菜单与 QML 电源菜单分别验收，不将其中一个通过记作另一个通过。测试无托盘恢复和 Explorer 重注册时，分别注明假平台结果与真实系统操作。

Shell 本地化夹具失败时额外记录自有目录的字面文本、ASCII/中文资源路径与系统资源对照，严格本地化断言保持；对照不扫描用户目录、不更改信任策略。#56 跟踪 Windows CI 返回物理名称的问题。[Microsoft KB5103160](https://support.microsoft.com/en-us/servicing/os/windows/docs/2026/06/custom-folder-icons-or-localized-folder-names-might-not-appear-after-installing-the-june-2026-window) 说明 desktop.ini 来源信任硬化是可能影响因素；MOTW、系统版本和原生 API 返回值只是诊断信息，不能单凭该公告确认本机根因或将失败视为通过。

针对 #56，hosted Windows 在工作区继续验证目录合并和路径身份，并将产品名称与独立调用的 Shell 正常显示名逐项比较：系统返回中文或物理名时均不得由产品自行改写。另在同一一次性 runner 的用户配置临时目录运行完整的严格本地化夹具，仍必须得到精确中文名称，且同显示名、不同路径不得合并；任一用例失败都使 CI 失败。CI 连续运行两轮并分别保存两个位置的证据。无 `desktop.ini` 的受控目录另验证物理名与路径身份；只给自建夹具的另一份 `desktop.ini` 添加来源标记，核对产品遵循系统选择，并在清理夹具时一同删除；独立目录记录先读后配置、通知与等待时序及文件系统信息。夹具不扫描用户目录、不修改系统信任策略；这一区分修正了测试对 Shell 始终采用自定义名称的假设，不声称已确定特定 runner 忽略该文件的系统原因。

`--smoke-test` 不连接真实目录、桌面动作、托盘或定位服务且无布局 IO 的行为单独验证；正常退出应等待待保存快照落盘，失败应有状态或日志并保留前一有效文件。正常窗口运行不等于已接管 Win 键、开始按钮或 Explorer。

## Windows 运行时截图与有效缩放

完成应用和测试构建后运行。正式默认缓存可直接赋给 `XDSTARTER_QT_ROOT`，或传入其他相同版本 SDK：

```powershell
$env:XDSTARTER_QT_ROOT = "$PWD/build/Qt/6.8.2/msvc2022_64"
./scripts/verify-windows-ui.ps1 -QtPrefix $env:XDSTARTER_QT_ROOT
./scripts/verify-windows-ui.ps1 -QtPrefix $env:XDSTARTER_QT_ROOT -NativeScales
```

第一条在 offscreen/software 下运行交互与截图检查；第二条在可见 Windows 桌面使用 Windows QPA 和默认图形后端。脚本先以 `QT_SCALE_FACTOR=1` 探测当前屏幕基础 DPR，再按 `目标 DPR / 基础 DPR` 校准 100/125/150/175/200% 的 Qt 有效缩放，并核对实际窗口 DPR。此前本机探测基础 DPR 为 1.5、后端 Direct3D 11；脚本不假定其他显示器具有同样数值。

原生输出目录为 `build/validation/ui/native-{100,125,150,175,200}/`，`native-matrix.json` 汇总基础 DPR、实际 DPR、图形 API 和被测程序校验值。每档保存六组深浅主题 × 三组的记录，每组包括完整窗口 PNG、网格裁剪 PNG 和 JSON；默认离屏输出到 `build/validation/ui/offscreen/`。测试对真实 `QQuickWindow` 抓帧并扫描物理像素，检查小/标准/宽磁贴的宽高、8 DIP 间隙、四小磁贴含中缝与标准外框相等、两标准磁贴含间隙与宽磁贴相等，允许光栅化边界最多 1 物理像素误差，同时确认主题切换不改变逻辑几何。

验证脚本将当前进程及其测试子进程的 `TEMP`/`TMP` 临时设为 `build/validation/ui/temp/`，避免受管桌面默认临时目录不可写使 QTemporaryDir 夹具失败；脚本通过 finally 恢复原环境，不修改系统/用户设置或产品保存逻辑。构建入口另使用 `build/tmp/`，两者用途分开记录。

几何抓帧只在测试夹具中把 ToolTip opacity 设为 0，避免浮层遮挡磁贴扫描；JSON 明确记录 `tooltipsHiddenForGeometryCapture: true`。像素取样避开图标字形抗锯齿区域，未修改产品 ToolTip 行为或放宽 1 物理像素容差。ToolTip 可见性与完整文本由独立交互用例验证，不能用这些几何抓帧判定提示浮层表现。

批量截图、JSON 和日志属于本地或 CI 工件，不提交到 Git。本轮仅将两张无用户数据的内存样例窗口 PNG 作为代表性验证图收录于 `technical/validation/issue-16/`；真实应用目录、布局目标描述和完整构建工件不随其提交。失败时保留实际 QPA、图形 API、窗口/屏幕几何、DPR 与像素扫描记录，避免仅凭 JSON 参数或设计稿认定布局通过。

此矩阵不修改 Windows 显示设置，不能替代系统设置中真实切换缩放、混合 DPI 跨屏拖动、拔插屏幕、原生开始菜单接管或屏幕阅读器焦点验收。其他 Qt 版本、MSVC 2022 应用 CI 与 macOS 构建也仍需各自验证。

## Issue #34：系统主题偏好

布局与导入测试覆盖 schema 1–4 严格兼容、旧文件备份及 schema 5 的 `system` 往返；GUI 测试在独立进程中模拟 Qt 外观提示变化，覆盖手动覆盖、未知值回退、导入、只读保护、保存与磁贴几何不变。自动化不改动 Windows 系统主题，不能替代真实系统切换、高对比度、减少动画及屏幕阅读器验收。实现与兼容决定见 [ADR-0018](adr/0018-system-theme-preference.md)。

减少动画实现按 [ADR-0019](adr/0019-reduced-motion.md) 在平台层只读 Windows 用户偏好。平台测试向本进程隐藏 Qt 窗口发送单条设置通知并注入读取结果，检查去重、失败回退和通知排队；GUI 用进程内偏好源测试窗口、目录、菜单、磁贴、索引、错误与拖放预览，包括进行中切换、几何和不写盘。测试不广播消息或更改系统设置；真实 Windows 设置切换、不同用户会话及屏幕阅读器验收仍需独立记录。

## 性能目标与方法

参考机记录 CPU、内存、GPU、磁盘、Windows 构建、Qt/编译器和 Release 构建参数。以 100 枚磁贴、1000 个应用目录项作为初始数据集，另外覆盖空布局和较大目录。
