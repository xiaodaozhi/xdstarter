# 许可与依赖决策

状态：项目代码与原创设计资产的发布许可证待项目所有者确定；本次初始化不添加未经确认的 LICENSE。

## 待确认事项

在 M0 的许可 Issue 中决定应用代码、文档和原创视觉资产的授权方式，并在 PR 中添加对应许可证文本与 README 说明。选择前不承诺访客具有通用复制、修改和分发权；仓库可见性由所有者单独管理，本次不修改私有/公开状态。

## Qt 许可方向

Qt 具有开源与商业许可选项。多数核心模块提供 LGPL 路径，部分模块的开源许可可能仅为 GPL。需要按实际使用模块核对，不以“使用 Qt”直接推导应用必须开源或必然免费发行。

当前架构倾向动态库部署，选择最终许可路线后核对通知、依赖许可文本、源代码提供/重新链接等适用要求。Qt LTS 维护与补丁可用性按取得的软件版本和许可渠道记录。

## 依赖清单要求

每个引入的第三方依赖记录名称、精确版本、上游地址、许可、用途、修改与再分发材料。拼音库/词库、图标、字体、安装器与测试工具也纳入清单。当前工程与 CI 的版本及来源见[工程依赖记录](../technical/dependencies.md)；Qt 二进制由开发者或 CI 取得，没有第三方运行库入库或安装包再分发。

设计稿中的第三方应用图标为简化示意，原始应用名称/标志归其权利人。品牌几何源和 PNG 字标分别记录；运行时使用系统字体与从已安装应用提取的图标，避免分发未获授权的字体或图标集合。

依据：[Qt 许可](https://doc.qt.io/qt-6/licensing.html)、[Qt LGPL 义务说明](https://www.qt.io/development/open-source-lgpl-obligations)。最终许可选择与发行审查结果以项目所有者确认及关联 Issue/PR 为准。
