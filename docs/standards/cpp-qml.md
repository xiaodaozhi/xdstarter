# C++ / QML 技术规范

## C++

- C++20，类/类型 PascalCase、函数和变量 camelCase，命名空间 `xdstarter`，文件采用 `lower_snake_case`。
- 使用 RAII 管理 COM、句柄、Hook 和线程生命周期。QObject 采用清晰 parent 所有权；跨线程对象遵守线程归属，不混用模糊的 shared ownership。
- 接口暴露结构化结果和错误信息，日志不替代失败返回。平台异常不穿越 Win32 回调或 QML 边界。
- 平台 API 放在 Windows 适配层，通用代码不包含 Windows 头文件；不得把宏与句柄泄漏到 QML 模型。
- 外部数据和启动目标先校验，启动时分离目标、参数、工作目录，不拼接任意 Shell 字符串。
- GUI 线程只做有界更新；阻塞 IO、目录扫描和大型搜索索引使用后台任务。

## QML

- 组件 PascalCase、属性/id/信号 camelCase；4 空格缩进，禁止混用 Tab。
- QML 负责呈现、交互与状态绑定；持久化、应用枚举、复杂布局计算和系统接管放在 C++。
- 使用命名主题 token，布局以逻辑单位为准。磁贴外框不能由文本 implicitWidth/Height 撑开。
- 保持可见焦点、Accessible 名称、ToolTip 与可键盘操作；小磁贴名称不因隐藏文字而丢失。
- 模型增量更新，避免每次键入重建整个对象树；避免无限绑定循环、隐藏时持续动画与全量轮询。
- 使用标准 QML 模块导入、显式依赖和 Qt Resource System，避免依赖工作目录寻找资源。

## 构建、格式与依赖

仓库 `.clang-format` 是 C++ 格式基准。QML 使用所选 Qt 版本的 qmlformat/qmllint，工具加入应用工程 CI 时固定版本与命令。

只引入有明确用途的依赖，记录版本、来源、许可证与更新方式。Qt 升级通过 PR，覆盖布局、图标、焦点、材料和部署回归。禁止在业务代码中硬编码开发者机器路径。

算法与状态转换的测试关注可观察行为和边界，不镜像内部实现。每个实际新增模块同时定义适用的测试层级。
