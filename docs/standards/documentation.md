# 文档与设计版本规范

文档以中文为主，文件名使用英文 kebab-case。代码标识符、提交信息、API 名称保留英文。Markdown 使用相对链接，仓库文件不能引用开发者绝对路径。

## 信息归属

- README 面向访客：价值、当前状态、设计预览、参与方式、真实可运行命令。
- product 保存用户需求与交互；technical 保存实现边界、数据与验证策略。
- ADR 保存已决定的技术取舍，包含日期、状态、背景、决定、影响与依据。
- Issue/PR 保存进度、任务拆分、负责人、讨论、实现和验收证据。

新增需求优先复用稳定 PRD 编号；重大变更更新相关文档并链接 Issue/PR。不要在多个文档维护互相竞争的状态表。尚未实现的接口和功能明确标为设计或计划。

## 设计资产

当前稿使用明确版本目录，源文件和导出一起提交；颜色与网格 token 保持可追溯。历史稿在 archive 中，并标明不用于当前验收。图像探索提示词保留在设计 source/prompts。

重建 PNG 的字体差异可能改变字形，因此几何与布局用共享数据检查，文字与图标仍须目视验收。第三方示意图标不能替代运行时系统图标。

## 检查与变更

提交前运行 `python3 scripts/check_repository.py`。该脚本检查仓库内链接与设计格式；外部链接内容、实际产品行为和许可需结合对应资料/环境审核。

GitHub 的 `.yml` 配置使用 JSON 语法（YAML 的合法子集），便于标准库进行确定性校验。修改时保持该语法，或在改变语法的 PR 中同步更新检查器。

不可用的安装或构建步骤不能写成当前可运行命令。引用外部技术事实优先使用官方文档并保留直接链接。
